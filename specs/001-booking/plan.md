# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

Spec ID: SPEC-BKG-001  
Spec version: Draft v2  
สถานะเอกสาร: รอทีมตรวจสอบ  
วันที่จัดทำ: 2569-09-16

## 1. สรุปแนวทาง

- ผู้รับบริการที่ยืนยันตัวตนแล้วค้นหาวัน ช่วงเวลา และจำนวนที่นั่งว่างภายใน 30 วัน (FR-BKG-01, IF-IDP-01)
- ระบบตรวจคิวเดิมและจำนวนที่นั่งอีกครั้งก่อนสร้างการจอง เพื่อรองรับการจองซ้ำและการแข่งขันระหว่างผู้ใช้ (FR-BKG-02, FR-BKG-03)
- เมื่อจองสำเร็จ ระบบบันทึกการจอง ตัดที่นั่ง ออกหมายเลขคิว และส่งคำขอแจ้งเตือนทันทีแบบ asynchronous (FR-BKG-04, IF-NOT-01, ASM-03)
- เมื่อแจ้งเตือนไม่สำเร็จ ระบบคงการจอง แสดงหมายเลขคิว และเริ่ม Retry รอบแรกไม่เกิน 5 นาที (FR-BKG-05, NFR-REL-02)
- การออกแบบต้องใช้ HN แทนเลขบัตรประชาชน บันทึก audit log และป้องกันเลขคิวซ้ำในระดับแผนกกับวันที่รับบริการ (IF-HIS-01, DOM-PDPA-01, ASM-04)

| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้าง API สำหรับค้นหา ตรวจสอบ และสร้างการจอง |

| TLS 1.2 ขึ้นไป | NFR-SEC-01 | ใช้เข้ารหัสข้อมูลการจองขณะรับส่ง |

## 3. โมเดลข้อมูล

| Entity / ตาราง | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Booking` | HN, package_id, service_date, time_slot_id, department_id, queue_number, status, created_at | FR-BKG-02, FR-BKG-04, FR-BKG-05, ASM-02, ASM-04 |
| `TimeSlot` | time_slot_id, service_date, department_id, package_id, capacity, remaining_seats | FR-BKG-01, FR-BKG-03, FR-BKG-06, ASM-01 |
| `NotificationJob` | booking_id, channel, status, requested_at, retry_at, first_retry_at | FR-BKG-04, FR-BKG-05, NFR-REL-02, IF-NOT-01 |
| `AuditLog` | accessor, accessed_at, patient_code, action | DOM-PDPA-01, AC-BKG-06 |
| `PatientReference` | HN, ข้อมูลอ้างอิงจาก HISที่จำเป็นต่อการจอง | IF-HIS-01 |

ข้อกำหนดข้อมูลสำคัญ:

- `Booking` ต้องไม่มีฟิลด์เลขบัตรประชาชน และใช้ HN เป็นข้อมูลอ้างอิงภายใน (IF-HIS-01)
- `Booking` ต้องมีขอบเขตความไม่ซ้ำของหมายเลขคิวที่ `department_id + service_date` (FR-BKG-04, ASM-04)
- ต้องเก็บสถานะที่ใช้ตรวจว่าเป็นคิวที่ “ยังไม่ได้ใช้” แต่ค่าของสถานะต้องรอคำตอบ Q-05 (FR-BKG-02)
- รายละเอียด quota มาจากข้อมูลที่ UC-09 จัดการไว้แล้ว แผนนี้ไม่สร้างส่วนจัดการ quota (ASM-01, UC-09)

## 4. API / หน้าจอ

| รายการ | Input หลัก | Output หลัก | รองรับ |
|---|---|---|---|
| `GET /booking/availability` | package_id, วันที่เริ่มต้น/สิ้นสุด, department_id | วัน ช่วงเวลา และจำนวนที่นั่งคงเหลือภายใน 30 วัน | FR-BKG-01, AC-BKG-05 |
| `GET /booking/patient-context` | ผลยืนยันตัวตนจาก IDP, ข้อมูลอ้างอิง HIS | HN และข้อมูลที่จำเป็นต่อการจอง โดยไม่ส่งเลขบัตรประชาชนให้ `Booking` | IF-IDP-01, IF-HIS-01 |
| `POST /booking` | HN, package_id, service_date, time_slot_id, department_id | ผลสำเร็จหรือเหตุผลปฏิเสธ พร้อม queue_number | FR-BKG-02, FR-BKG-03, FR-BKG-04, AC-BKG-01, AC-BKG-02, AC-BKG-03 |
| `GET /booking/{booking_id}` | booking_id | รายละเอียดการจองและหมายเลขคิว | FR-BKG-04, AC-BKG-01, DOM-PDPA-01 |
| หน้าค้นหาและเลือกเวลา | package_id, วันที่, ช่วงเวลา | รายการวัน ช่วงเวลา และที่นั่งคงเหลือ | FR-BKG-01, FR-BKG-06 |
| หน้ายืนยันการจอง | รายการที่เลือก | ผลสำเร็จ หมายเลขคิว หรือข้อความปฏิเสธ/ช่วงเวลาเต็ม | FR-BKG-02, FR-BKG-03, FR-BKG-04, FR-BKG-05 |

| IF-NOT-01 | `NotificationJob` และการส่งคำขอแบบ asynchronous ทันทีหลัง `POST /booking` | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-BKG-01 | `test_AC_BKG_01_booking_success` | เตรียมช่วง 09.00 น. เหลือ 1 ที่และไม่มีคิวในแผนก/วันที่เดียวกัน จากนั้นยืนยันและตรวจว่าบันทึกการจอง แสดงหมายเลขคิว และที่นั่งเหลือ 0 (FR-BKG-04, ASM-04) |
| AC-BKG-02 | `test_AC_BKG_02_reject_unused_same_day_booking` | เตรียมคิวที่ยังไม่ได้ใช้ แล้วพยายามจองวันเดียวกัน ตรวจว่าถูกปฏิเสธและแสดงหมายเลขคิวเดิม (FR-BKG-02, Q-05) |
| AC-BKG-03 | `test_AC_BKG_03_full_slot_no_duplicate_booking` | ให้ผู้ใช้หนึ่งคนจองที่นั่งสุดท้ายก่อน แล้วให้ผู้ใช้อีกคนยืนยัน ตรวจข้อความเต็ม ตัวเลือกใกล้เคียง 3 รายการ และไม่มีการจองซ้อน (FR-BKG-03, Q-01) |
| AC-BKG-04 | `test_AC_BKG_04_notification_retry` | จำลองระบบแจ้งเตือนไม่ตอบสนอง ตรวจว่าการจองยังอยู่ แสดงหมายเลขคิว ส่งคำขอทันที และมี Retry รอบแรกไม่เกิน 5 นาที (FR-BKG-05, NFR-REL-02, IF-NOT-01) |

## 7. ลำดับงาน

1. ยืนยันทีมเลือกเทคโนโลยีที่ไม่ได้ระบุใน spec และกำหนดขอบเขต integration ของ IDP, HIS และระบบแจ้งเตือน (CON-TECH-01, IF-IDP-01, IF-HIS-01, IF-NOT-01)
2. ออกแบบตาราง `Booking`, `TimeSlot`, `NotificationJob`, `AuditLog` และข้อจำกัด HN/เลขคิว โดยไม่สร้างฟิลด์เลขบัตรประชาชนใน `Booking` (IF-HIS-01, ASM-04)
3. สร้างการค้นหาช่วงเวลาว่างภายใน 30 วันและการคำนวณใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-01, FR-BKG-06)
4. สร้างการตรวจคิวเดิมและตรวจที่นั่งซ้ำในจุดยืนยัน พร้อมกรณีช่วงเวลาเต็ม (FR-BKG-02, FR-BKG-03)
5. สร้างการบันทึกการจอง ตัดที่นั่ง และออกหมายเลขคิวแบบไม่ซ้ำในขอบเขตแผนก/วันที่รับบริการ (FR-BKG-04, AC-BKG-01, ASM-04)
6. เชื่อมการส่งข้อความแบบ asynchronous และสร้างคิว Retry รอบแรกไม่เกิน 5 นาที (FR-BKG-05, NFR-REL-02, AC-BKG-04)
7. เพิ่มการบันทึก audit log และการเข้ารหัสการรับส่งข้อมูล (DOM-PDPA-01, NFR-SEC-01, AC-BKG-06)
8. รันทดสอบตาม AC-BKG-01 ถึง AC-BKG-06 รวม load test ที่ 200 ผู้ใช้พร้อมกัน และบันทึกผลที่ตรวจรับได้ (NFR-PERF-01, NFR-USE-01)

## 8. สิ่งที่ยังไม่ทำ

ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

- Q-01 "ช่วงเวลาใกล้เคียง" นับเฉพาะวันเดียวกัน หรือรวมวันถัดไปด้วย? -> ถามพยาบาลคัดกรอง
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (FR-BKG-03, AC-BKG-03)
- Q-03 "ยืนยันภายใน 3 นาที" เริ่มจับเวลาตั้งแต่เหตุการณ์ใด และใช้เกณฑ์สำเร็จกี่เปอร์เซ็นต์? -> ถามทีมเอง
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (Goal, NFR-USE-01)
- Q-04 "กระจายผู้รับบริการได้สมดุลตามโควตา" ใช้ตัวชี้วัดและค่าเกณฑ์ใด? -> ถามทีมเอง/ผู้ดูแลตารางคิว
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (Goal, ASM-01)
- Q-05 สถานะใดของคิวถือว่า "ยังไม่ได้ใช้"? -> ถามเจ้าหน้าที่เวชระเบียน
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (FR-BKG-02, AC-BKG-02)
- Q-06 เมื่อ IDP หรือ HIS ไม่ตอบสนองหรือไม่พบข้อมูล ระบบต้องแสดงผลและให้ทำอะไรต่อ? -> ถามทีมเอง/ผู้ดูแลระบบ IDP และ HIS
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (IF-IDP-01, IF-HIS-01)
- Q-07 เมื่อเปลี่ยนแพ็กเกจ ต้องใช้เงื่อนไขใดคำนวณช่วงเวลาว่าง และต้องล้างช่วงเวลาที่เลือกหรือไม่เมื่อไม่รองรับ? -> ถามทีมเอง/เจ้าหน้าที่ผู้จัดแพ็กเกจ
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (FR-BKG-06)
