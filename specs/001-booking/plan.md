# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

Spec ID: SPEC-BKG-001  
Spec version: Draft v2  
สถานะเอกสาร: รอทีมตรวจสอบ  
วันที่จัดทำ: 2569-09-16

## 1. เป้าหมายและขอบเขต

ระบบต้องรองรับการค้นหาช่วงเวลาว่างและจองคิวตรวจสุขภาพสำหรับผู้รับบริการที่ยืนยันตัวตนแล้ว โดยครอบคลุม FR-BKG-01 ถึง FR-BKG-06 และ AC-BKG-01 ถึง AC-BKG-06

อยู่นอกแผนนี้: การยืนยันตัวตน (UC-13), การยกเลิกหรือเลื่อนคิว (UC-02), การชำระค่าบริการ (UC-03) และการจัดการตารางคิวหรือโควตา (UC-09)

## 2. ข้อจำกัดและข้อสมมติที่ใช้

- ใช้ MySQL ตาม CON-TECH-01
- ต้องบันทึก audit log ตาม DOM-PDPA-01 และเก็บอย่างน้อย 1 ปี
- ต้องตรวจผลจาก IDP ก่อนเข้าถึงข้อมูลผู้รับบริการตาม IF-IDP-01
- ใช้ HN เป็นข้อมูลอ้างอิงภายใน และไม่เก็บเลขบัตรประชาชนในตารางการจองตาม IF-HIS-01
- ส่งข้อความผ่าน SMS/LINE แบบ asynchronous และส่งคำขอทันทีหลังยืนยันการจองตาม IF-NOT-01 และ ASM-03
- Retry รอบแรกต้องเริ่มไม่เกิน 5 นาทีเมื่อส่งข้อความไม่สำเร็จตาม FR-BKG-05, NFR-REL-02 และ ASM-03
- หมายเลขคิวรีเซ็ตเวลา 00:00 น. Asia/Bangkok และไม่ซ้ำกันภายในแผนกกับวันที่รับบริการตาม ASM-04
- เทคโนโลยีภาษา framework และส่วนประกอบอื่นนอกเหนือจาก MySQL: ทีมเลือกเอง ไม่ได้มาจาก spec

## 3. องค์ประกอบหลัก

### 3.1 โมดูลค้นหาช่วงเวลาว่าง

- รับแพ็กเกจและช่วงวันที่ที่อยู่ภายใน 30 วันข้างหน้า
- แสดงวัน ช่วงเวลา และจำนวนที่นั่งคงเหลือตาม FR-BKG-01
- คำนวณผลลัพธ์ใหม่เมื่อผู้รับบริการเปลี่ยนแพ็กเกจตาม FR-BKG-06
- ต้องวัด p95 ที่ผู้ใช้พร้อมกัน 200 คนตาม NFR-PERF-01

### 3.2 โมดูลยืนยันการจอง

- ตรวจว่าผ่าน IDP และสามารถอ้างอิงข้อมูลผู้รับบริการด้วย HN ตาม IF-IDP-01 และ IF-HIS-01
- ตรวจคิวเดิมที่ยังไม่ได้ใช้ในวันเดียวกันตาม FR-BKG-02
- ตรวจจำนวนที่นั่งซ้ำอีกครั้งขณะยืนยัน เพื่อรองรับกรณีช่วงเวลาเต็มระหว่างการเลือกตาม FR-BKG-03
- เมื่อสำเร็จ ให้บันทึกการจอง ตัดที่นั่ง ออกหมายเลขคิว และส่งคำขอแจ้งเตือนทันทีตาม FR-BKG-04
- การบันทึกการจองและการตัดที่นั่งต้องทำเป็นหน่วยเดียวกัน เพื่อไม่ให้เกิดรายการจองที่บันทึกแล้วแต่จำนวนที่นั่งไม่สอดคล้อง

### 3.3 โมดูลแจ้งเตือนและ Retry

- รับคำขอแจ้งเตือนหลังการจองสำเร็จโดยไม่ทำให้การจองรอผลการส่ง
- หากส่งไม่สำเร็จ ต้องคงรายการจองและแสดงหมายเลขคิว
- บันทึกรายการที่ต้อง Retry และเริ่ม Retry รอบแรกไม่เกิน 5 นาทีตาม FR-BKG-05 และ NFR-REL-02

### 3.4 โมดูล audit log

- บันทึกผู้เข้าถึง เวลา และรหัสผู้รับบริการทุกครั้งที่เข้าถึงข้อมูลสุขภาพตาม DOM-PDPA-01
- เก็บข้อมูลไม่น้อยกว่า 1 ปี
- ต้องไม่บันทึกเลขบัตรประชาชนในตารางการจองตาม IF-HIS-01

## 4. แบบจำลองข้อมูลเชิงตรรกะ

รายละเอียดฟิลด์และชื่อจริงให้ทีมเลือกในขั้นออกแบบ โดยต้องรักษาข้อกำหนดต่อไปนี้:

- การจองต้องอ้างอิงผู้รับบริการด้วย HN ไม่ใช่เลขบัตรประชาชน (IF-HIS-01)
- การจองต้องผูกกับแพ็กเกจ วันที่รับบริการ ช่วงเวลา และแผนก เพื่อรองรับ FR-BKG-01, FR-BKG-04 และ ASM-04
- ต้องเก็บสถานะการจองเพื่อรองรับการตรวจคิวที่ยังไม่ได้ใช้ตาม FR-BKG-02 โดยนิยามสถานะต้องรอคำตอบ Q-05
- ต้องมีข้อมูลจำนวนที่นั่งหรือแหล่งข้อมูลโควตาที่อ่านได้จาก UC-09 ตาม ASM-01
- ต้องมีข้อมูลคิวแจ้งเตือนที่ระบุสถานะความล้มเหลวและเวลาที่ต้องเริ่ม Retry ตาม FR-BKG-05 และ NFR-REL-02
- ต้องมีข้อมูล audit log ตาม DOM-PDPA-01

ข้อจำกัดความไม่ซ้ำของหมายเลขคิวต้องอยู่ที่ระดับ `แผนก + วันที่รับบริการ` และใช้เวลา Asia/Bangkok ตาม ASM-04

## 5. ลำดับการทำงานหลัก

1. ตรวจผลการยืนยันตัวตนจาก IDP ก่อนอ่านข้อมูลผู้รับบริการ (IF-IDP-01)
2. ค้นข้อมูลผู้รับบริการจาก HIS และใช้ HN ภายในระบบ (IF-HIS-01)
3. ค้นหาและแสดงช่วงเวลาว่างภายใน 30 วัน พร้อมจำนวนที่นั่ง (FR-BKG-01)
4. เมื่อเปลี่ยนแพ็กเกจ ให้คำนวณช่วงเวลาว่างใหม่ (FR-BKG-06)
5. เมื่อยืนยันการจอง ให้ตรวจคิวเดิมและจำนวนที่นั่งล่าสุด (FR-BKG-02, FR-BKG-03)
6. หากผ่านการตรวจ ให้บันทึกการจอง ตัดที่นั่ง ออกหมายเลขคิว และส่งคำขอแจ้งเตือนทันที (FR-BKG-04, IF-NOT-01)
7. หากแจ้งเตือนไม่สำเร็จ ให้คงการจอง แสดงหมายเลขคิว และจัดรายการ Retry รอบแรกไม่เกิน 5 นาที (FR-BKG-05, NFR-REL-02)
8. บันทึก audit log เมื่อมีการเข้าถึงข้อมูลสุขภาพ (DOM-PDPA-01)

## 6. การจัดการกรณีแข่งขันและความสอดคล้องของข้อมูล

- การยืนยันการจองต้องตรวจที่นั่งซ้ำ ณ จุดบันทึกจริง เพื่อให้ AC-BKG-03 ไม่เกิดรายการจองซ้อน
- การออกหมายเลขคิวต้องป้องกันหมายเลขซ้ำภายใน `แผนก + วันที่รับบริการ` ตาม AC-BKG-01 และ ASM-04
- การตัดที่นั่งและการสร้างรายการจองต้องสำเร็จหรือไม่สำเร็จไปพร้อมกัน
- หากการส่งแจ้งเตือนล้มเหลว ห้ามย้อนกลับรายการจองตาม FR-BKG-05

## 7. แผนการทดสอบและการตรวจรับ

| งานทดสอบ | ข้อกำหนดที่ตรวจ | เกณฑ์หลัก |
|---|---|---|
| ค้นหาช่วงเวลาว่าง | FR-BKG-01, AC-BKG-05, NFR-PERF-01 | แสดงช่วงเวลาและที่นั่งครบ และ p95 ไม่เกิน 2 วินาทีที่ผู้ใช้พร้อมกัน 200 คน |
| จองสำเร็จ | FR-BKG-04, AC-BKG-01 | บันทึกการจอง ตัดที่นั่งเป็น 0 ออกเลขคิวถูกขอบเขต และส่งคำขอแจ้งเตือนทันที |
| จองซ้ำวันเดียวกัน | FR-BKG-02, AC-BKG-02 | ปฏิเสธและแสดงเลขคิวเดิม |
| ช่วงเวลาเต็มระหว่างยืนยัน | FR-BKG-03, AC-BKG-03 | แจ้งช่วงเวลาเต็ม แสดง 3 ตัวเลือก และไม่สร้างรายการจองซ้อน |
| แจ้งเตือนล้มเหลว | FR-BKG-05, AC-BKG-04, NFR-REL-02 | การจองยังอยู่ แสดงเลขคิว และเริ่ม Retry รอบแรกไม่เกิน 5 นาที |
| Audit log | DOM-PDPA-01, AC-BKG-06 | มีผู้เข้าถึง เวลา และรหัสผู้รับบริการ และไม่เก็บเลขบัตรประชาชนในรายการจอง |
| การรับส่งข้อมูล | NFR-SEC-01 | ข้อมูลการจองระหว่างรับส่งใช้ TLS 1.2 ขึ้นไป |

ชื่อชุดทดสอบควรอ้างอิง AC ID เช่น `AC-BKG-01` และ `AC-BKG-04` ตามกฎของโครงการ

## 8. สิ่งที่ต้องตอบก่อนลงรายละเอียดหรือเริ่มพัฒนา

รายการต่อไปนี้เป็น blocker จาก spec และห้ามตัดสินใจแทนทีม:

- Q-01: ขอบเขตและลำดับของ “ช่วงเวลาใกล้เคียง” 3 ตัวเลือก
- Q-03: จุดเริ่มต้นและเกณฑ์วัด “ยืนยันภายใน 3 นาที”
- Q-04: ตัวชี้วัดของการกระจายผู้รับบริการอย่างสมดุล
- Q-05: สถานะที่ถือว่า “ยังไม่ได้ใช้”
- Q-06: พฤติกรรมเมื่อ IDP หรือ HIS ไม่ตอบสนองหรือไม่พบข้อมูล
- Q-07: เงื่อนไขการคำนวณช่วงเวลาหลังเปลี่ยนแพ็กเกจ และการจัดการช่วงเวลาที่เลือกไว้
